# せせらぎ (Seseragi) 仕様書

## 1. コンセプト

> 雨音とピアノを、かさねて眠る。

眠るときに「雨の音」と「好きなピアノ曲」を同時に流したい——
そのための、**2つの独立した音の流れを1つの画面で操るプレイヤー**。

ビジュアルは**清流**。深い青緑のグラデーションの上を、静かな波がゆっくり流れる。
夜に見ても眩しくないダークトーンで統一する。

## 2. 用語

| 用語 | 意味 |
|---|---|
| デッキ（ながれ） | 独立した1系統のプレイヤー。本アプリには「ながれ A」「ながれ B」の2つがある |
| キュー | デッキに読み込まれた曲のリスト（＝そのデッキのプレイリスト） |

### 2デッキのハイブリッド構成

2つのデッキは再生エンジンが異なり、それぞれ得意なことが違う。

| | ながれ A（ライブラリ） | ながれ B（ミュージック） |
|---|---|---|
| 選曲 | 端末ライブラリのピッカー | **Apple Music カタログ全体を検索**（MusicKit） |
| エンジン | `AVAudioPlayer`（ファイル再生） | `MPMusicPlayerController.systemMusicPlayer` |
| Apple Music・DRM 曲 | ❌ 再生不可 | ✅ **すべて再生可能** |
| ライブラリ未追加の曲 | ❌ | ✅（検索して直接再生） |
| アプリ内の独立音量 | ✅ スライダーで調整 | ❌ 本体音量と連動 |
| スリープタイマーのフェード | ✅ | ❌（停止のみ） |
| リピート（一曲/リスト/なし） | ✅ | ✅ |

**使い分けの想定**: 雨音などの環境音（購入曲・取り込み曲・ファイル）を ながれ A に、
Apple Music のピアノプレイリストを ながれ B に置き、
音量バランスは「本体音量で全体を決め、ながれ A のスライダーで環境音の混ざり具合を調整」する。

## 3. 機能要件

### F-1. 2デッキ並列再生
- 2つのデッキが**同時に**音声を再生できる。
- 片方だけの再生、両方の再生、どちらも自由に行える。
- 一方のデッキ操作が他方の再生に影響しない。

### F-2. 選曲
- 複数曲の同時選択に対応し、選んだ曲がそのままデッキのキューになり自動再生する。
- **ながれ A（端末ライブラリ）**: `MPMediaPickerController` で端末内の曲を選ぶ。
  「ファイルの実体が端末にない曲」のみ事前除外し（ピッカーでもクラウド曲は非表示）、
  それ以外はできる限り再生を試み、失敗した曲はスキップ。除外時は件数と対処を通知する。
- **ながれ B（Apple Music）**: 「ライブラリ」と「検索」の2タブ構成。
  - **ライブラリタブ**: 自分のライブラリの**プレイリスト / アーティスト / アルバム / 曲**を
    閲覧して選ぶ（MusicKit `MusicLibraryRequest`）。
  - **検索タブ**: Apple Music カタログ**全体**を検索（`MusicCatalogSearchRequest`）。
    結果は曲・プレイリスト・アルバム・アーティストで表示し、コンテナは中に入って選べる。
    ライブラリ未追加の曲でもそのまま再生できる（ストリーミング曲・DRM 曲を含む全曲対応）。
  - どちらのタブでも複数選択・「すべて追加」（プレイリスト/アルバム単位）に対応し、
    選んだ順に再生キューへ積む。検索は約350ms のデバウンス実行。

### F-3. 音量調整
- **ながれ A**: 0〜100% の音量スライダーを持ち、変更は再生中に即時反映される。
  端末のマスター音量とは独立した、アプリ内ミックスバランスとして機能する。
- **ながれ B**: iOS の仕様（システムプレイヤーはアプリからの音量操作不可）により
  本体音量と連動する。カード上にその旨を明記する。
- 2曲のバランスは「本体音量で全体、ながれ A のスライダーで混ざり具合」を調整する。

### F-4. リピート（デッキ独立）
- デッキごとに以下の3モードをボタンで巡回切替できる。
  1. **プレイリストリピート**（初期値）: キューの最後まで再生したら先頭に戻る
  2. **一曲リピート**: 現在の曲を繰り返す
  3. **リピートなし**: キューの最後の曲が終わったら停止する

### F-5. 再生操作（デッキ独立）
- 再生 / 一時停止
- 次の曲へスキップ
- 前の曲へ（再生位置が3秒を超えている場合は曲頭に戻る。3秒以内なら前の曲へ）
- 現在の曲名・アーティスト名・アートワーク・再生位置 / 曲の長さ・「n / m 曲」を表示する。

### F-6. 全体操作
- 「すべて再生 / すべて一時停止」ボタンで両デッキをまとめて操作できる。

### F-7. おやすみタイマー
- 15 / 30 / 45 / 60 / 90 分のプリセットから選択。
- 残り時間を mm:ss で表示。途中解除が可能。
- 終了時に両デッキを一時停止する。ながれ A は最後の20秒で音量をゆっくりフェードアウトする
  （ながれ B は音量操作不可のため停止のみ）。
- フェードはユーザーが設定した音量バランスを壊さない（内部係数で減衰し、解除時に元へ戻る）。

### F-8. バックグラウンド再生・ロック画面
- 画面を消しても、他アプリに切り替えても両デッキの再生が続く。
  - ながれ A: `UIBackgroundModes: audio` による本アプリのバックグラウンド再生
  - ながれ B: システムプレイヤー（Music アプリ）自身が再生を継続
- ロック画面 / コントロールセンターには **ながれ B が「ミュージック」として表示**され、
  ネイティブに操作できる（再生/停止・曲送り・スクラブすべて可能）。
- ながれ A はミックス再生セッション（`mixWithOthers`）のため、ロック画面には
  表示されないことがある。ながれ A の操作はアプリ画面で行う。

### F-9. 権限ハンドリング
- 初回起動時にミュージックライブラリへのアクセス許可（`NSAppleMusicUsageDescription`）を要求する。
- 拒否された場合は説明と「設定を開く」ボタンを表示する。

### F-10. 割り込み処理
- 電話着信などのオーディオ割り込みが発生したら両デッキを一時停止する。

## 5. 画面仕様

1画面構成。上から:

```
┌─────────────────────────┐
│        せせらぎ            │  ← タイトル
│  ふたつの流れを、かさねて眠る │
│ ┌─────────────────────┐ │
│ │ 〰 ながれ A     [選曲] │ │  ← デッキカード A（水色）
│ │ [🎨] 曲名             │ │     アートワーク・曲情報
│ │      アーティスト  1/12 │ │
│ │ ▬▬▬▬▬▬░░░░  1:23/4:56 │ │     進行バー
│ │  🔁   ⏮  ▶️  ⏭        │ │     リピート・スキップ・再生
│ │  🔈 ──────●──── 🔊    │ │     音量スライダー
│ └─────────────────────┘ │
│ ┌─────────────────────┐ │
│ │ 〰 ながれ B     [選曲] │ │  ← デッキカード B（若草色）
│ │        （同上）         │ │
│ └─────────────────────┘ │
│ [▶ すべて再生]  [🌙 タイマー] │  ← 全体操作バー
└─────────────────────────┘
       背景: 清流（波のアニメーション）
```

### 状態
- **権限未許可**: デッキの代わりに説明カードと「設定を開く」を表示
- **キューが空のデッキ**: 「ミュージックから曲を選ぶ」の大きなボタンを表示
- **タイマー作動中**: ボタンに残り時間（例「おやすみ 12:34」）を表示

### カラー
- 背景: 深い青〜青緑のグラデーション + 半透明の波レイヤー3枚がゆっくり流れる
- デッキ A: 水色系 / デッキ B: 若草色系（清流の水面と岸辺のイメージ）
- カードは `ultraThinMaterial`（すりガラス）で水の透明感を表現

## 6. 制約事項（重要）

### なぜ2デッキで方式が違うのか

DRM 曲（Apple Music）を再生できる唯一の手段である `MPMusicPlayerController` は、
**1アプリから同時に1系統しか再生できない**。そのため:

- 片方のデッキ（ながれ B）だけをシステムプレイヤーにして DRM 曲に対応し、
- もう片方（ながれ A）は `AVAudioPlayer` によるファイル再生として
  独立音量・フェードを担う、

というハイブリッド構成を採る。両者を同時に鳴らすため、アプリの
オーディオセッションは `.playback + .mixWithOthers` に設定する。

### MusicKit の有効化が必要（重要）

ながれ B のカタログ検索は MusicKit を使うため、**Apple Developer ポータルで
この App ID に MusicKit サービスを有効化する**必要がある。これには
**有料の Apple Developer Program 加入が必須**（無料の個人開発アカウントでは MusicKit を使えない）。
また、実際にストリーミング再生するには端末で **Apple Music のサブスクリプション**が有効であること。

手順の概要:
1. developer.apple.com → Certificates, IDs & Profiles → Identifiers で本アプリの App ID を開く
2. App Services の **MusicKit** を有効化して保存
3. Xcode で対象デバイス向けに再ビルド（プロビジョニングは自動更新される）

### ながれ A で再生できる曲 / できない曲

| 曲の種類 | ながれ A | ながれ B |
|---|---|---|
| iTunes Store で購入し**端末にダウンロード済み**の曲 | ✅ | ✅ |
| CD 取り込み・PC から同期した曲（端末に実体あり） | ✅ | ✅ |
| ファイル転送した DRM フリー曲 | ✅ | ✅ |
| iCloud 上にあり端末に**未ダウンロード**の曲 | ❌ | ✅ |
| Apple Music（サブスク）のストリーミング曲 | ❌ | ✅ |
| Apple Music の曲をダウンロードしたもの | ❌ | ✅ |
| 古い iTunes DRM（FairPlay, ~2009年購入の .m4p） | ❌ | ✅ |

**購入曲・CD 曲でも ながれ A で弾かれる場合**、原因はほぼ「iCloud ミュージック
ライブラリ（設定 →ミュージック→ライブラリを同期）経由で、実体ファイルが端末に
ないこと」。ミュージックアプリで該当曲の「⋯ → ダウンロード」を実行して
実体を落とせば ながれ A で再生できるようになる。それが面倒な場合は、
ながれ B のカタログ検索で同じ曲を探して流す（こちらはダウンロード不要）。

**実装上の扱い（ながれ A）**:
- ピッカーでは `showsCloudItems = false` により未ダウンロードの曲を非表示
- 事前除外は `assetURL == nil`（実体なし）のみ。それ以外は再生を試み、
  失敗した曲は自動スキップ。除外・スキップ件数はアラートで通知

### ながれ B（システムプレイヤー）の副作用
- 再生キューは Music アプリと共有される（Music アプリを開くと ながれ B の曲が表示される）。
- リピート設定も Music アプリの設定と連動する。
- アプリ内独立音量・フェードアウトは不可（本体音量と連動）。

### その他
- シミュレータにはミュージックライブラリが存在しないため、動作確認は実機で行う。
- おやすみタイマーは再生中のみ正確に動作する（オーディオ再生がアプリをバックグラウンドで生かし続けるため。両デッキ停止中はタイマーが遅延する可能性がある）。
